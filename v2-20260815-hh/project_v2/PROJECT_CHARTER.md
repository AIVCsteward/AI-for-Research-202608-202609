# GOAI 虚拟细胞 V2 项目章程

## 1. 项目目标

我们面向 GOAI AI for Research 算法赛虚拟细胞方向，构建能够外推到未见化合物、未见菌株及二者同时未知条件的酵母蛋白质组响应模型。

新版项目不以扩大模型规模为主要目标，而以三个可验证能力为核心：

1. 用可迁移的化学结构表征预测新化合物响应。
2. 用可靠映射的菌株基因组表征预测新遗传背景及其药物调制。
3. 分离基础生物状态、药物扰动响应和测量过程偏差，避免批次捷径。

## 2. 科学问题与预测形式

输入包括菌株、化合物、培养基、温度、处理时间及测量上下文，输出为固定蛋白列表的 log2 蛋白强度向量。

核心分解为：

```text
y_pred = y_baseline + delta_response + delta_batch
```

- `y_baseline`：指定菌株和培养条件下的无药基础状态。
- `delta_response`：化合物在该菌株和条件下造成的蛋白响应。
- `delta_batch`：data_source、instrument、plate/well 引入的测量偏差。

## 3. 比赛约束

### 3.1 标签边界

- 训练仅可使用 `split_final=train` 的蛋白质组标签。
- 验证集与测试集不得参与训练，也不得用于蛋白过滤、归一化、PCA、响应先验、相似药物 FC 或其他标签统计量估计。
- 外部实体特征可以为训练、验证和测试实体生成，但生成过程不得读取验证或测试蛋白标签。
- 测试蛋白真值仅可在赛题明确允许的独立自评流程中使用，且必须与训练、模型选择和特征构建完全隔离；默认 V2 开发流程不读取测试真值。

### 3.2 数据处理

- 元数据和蛋白矩阵必须按 `sample_ID` 对齐。
- raw intensity 在合法非缺失位置转换为 log2。
- NA 不等于 0；损失和指标必须 mask-aware。
- 蛋白保留列表、均值、标准差和降维参数只能由训练数据产生。
- 最终提交为 log2 尺度，不能提交内部 z-score。

### 3.3 外部资源

- 允许使用公开外部资源构建实体或蛋白先验特征。
- 必须记录来源 URL、版本/发布日期、下载日期、许可、校验值和处理脚本。
- 比赛原始数据不得上传到公开仓库。
- 大型外部原始文件原则上不提交 Git，只提交来源清单、下载脚本、处理脚本和必要的小型派生特征。

## 4. V2 主模型

### 4.1 基础状态分支

输入：菌株基因组、培养基、温度、时间。

禁止输入：化合物、SMILES、data_source、instrument、plate/well。

输出：`y_baseline`。

### 4.2 化合物分支

第一版输入：

- PubChem 核对后的 SMILES；
- RDKit Morgan fingerprint；
- RDKit 分子描述符；
- 结构映射合法性和置信度标记。

第一版不从头训练分子 GNN。冻结的预训练分子表示只能在 Morgan + 描述符基线完成后作为独立消融加入。

### 4.3 菌株分支

第一版使用 1011 酵母基因组项目或可信公开资源得到的简单特征，包括 SNP/indel、基因区变异负担、基因缺失/拷贝数及按通路聚合的变异。DHY210 使用 S288C 时必须标为代理。无法可靠映射的菌株使用显式 unknown/low-confidence 回退，不得伪造对应关系。

### 4.4 药物—菌株交互

化合物表示、菌株表示和培养条件通过小型门控、FiLM 或双线性交互产生 `delta_response`。control 的生物扰动响应必须强制或约束为零。

### 4.5 相似药物迁移

使用训练化合物的 Morgan/Tanimoto 相似度与仅由训练标签计算的平均 FC，产生相似药物参考响应。该分支与神经网络响应通过相似度门控融合。低相似度实体必须采用保守回退，不能强行迁移。

### 4.6 批次校正

批次分支只能接收 `data_source`、`instrument`、`Yeast_cell_plate` 和经 Main 批准的测量字段。禁止接收化合物、菌株、培养基、温度、时间或由这些变量衍生的 embedding。

### 4.7 蛋白输出

第一版优先使用低秩蛋白响应解码，降低高维小样本方差。GO/KEGG/STRING 先用于响应 basis、轻度通路正则和科学解释，不使用旧式单参数最终输出平滑作为主模型。

## 5. 损失与指标

损失按以下顺序逐项加入：

1. mask-aware Huber 或 MSE；
2. 严格 matched-control FC loss；
3. 基于训练集冻结阈值的高效应蛋白加权；
4. 小权重通路或图正则。

不得一次同时加入多个尚未验证的损失。每个新增损失必须有关闭该损失的对照。

评估必须按 `val_chem_only`、`val_strain_only`、`val_both` 和 `val_time` 分别报告，并同时记录绝对误差、逐样本/逐蛋白指标、FC、残差和 DEP 类诊断。正式计算细节以通过数据合同审计的实现为准。

## 6. 必做反证实验

- 正确 chemical embedding 对比 shuffle 和 zero。
- 正确 genome embedding 对比 shuffle 和 zero。
- 有/无相似药物迁移。
- 有/无批次分支，以及批次字段打乱。
- Huber only 对比 Huber + FC。
- 多随机种子与新批次留出。

只有正确 embedding 稳定优于 shuffle/zero，才能声称模型利用了外部知识。

## 7. 暂不采用的主线

- chemical hash 作为新药主要表示；
- 所有 head 接收相同输入的无约束残差分解；
- 能接收生物条件的批次校正；
- 单参数最终输出平滑 GNN；
- 第一阶段使用 Flow Matching、Diffusion、大型 Transformer、Genome LM 或从头训练分子 GNN。

它们可以作为后续研究备选，但必须在简单基线和接口冻结后独立验证。

## 8. 协作和 Git 规则

- `main` 仅由团队明确授权后合并，不允许执行线程直接修改或推送。
- 建议分支：`audit-data-contract`、`feature-chemistry`、`feature-genome`、`model-v2`、`protein-prior-v2`。
- 每个线程只修改分配目录；公共接口变更先报告 Main。
- 执行线程不得替代其他线程完成其职责，以免形成重复和冲突实现。
- 每次交付必须包含分支、commit、文件清单、运行命令、测试、结果、失败项和待 Main 决策问题。

## 9. 当前必须先解决的问题

1. 当前真实数据保留 4,422 个蛋白，而教程报告 4,232 个，原因尚未冻结。
2. 最终 feature contract 尚需依据真实文件、预处理和官方要求确认。
3. Water/DMSO 与 exact matched-control 规则需固化为可复用接口。
4. BAH、BAI、CEK、CGD、CRD 的公开基因组映射需提供证据；DHY210→S288C 仅为代理。
5. 当前规划版评分规则可能更新，正式提交前必须再次核对官方发布版本。
